> **版本**：v1.0  
> **依据**：需求文档4.md（663 行）、后端 routers 目录（12 个路由文件）、后端 models 目录（19 张表）、前端 pages 目录（10 个页面）、前端 admin 目录（6 个管理页面）  
> **目标**：清晰列出所有功能模块及其子功能，说明各模块的设计与实现思路

## 功能模块划分总表

|:---|:---|:---:|:---|:---|

## 模块详细设计

### FD01 — 店铺信息管理模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD01-01 | 创建店铺 | `UploadShopPage.tsx` | `POST /shops/` |
| FD01-02 | 上传店铺图片/菜单 | `ShopDetailPage.tsx`（上传组件） | `POST /images/`, `POST /menu/` |
| FD01-03 | 提交店铺信息勘误反馈 | 店铺详情页 | `POST /feedbacks/`（type=edit_request） |
| FD01-04 | 提交重复店铺反馈 | 店铺详情页 | `POST /feedbacks/`（JSON 含 candidate IDs） |

**设计实现思路**：  
店铺核心数据存入 `shops` 表，品类/区域等标签属性通过字典体系（`DictTypes` + `DictData` + `DictRel` 多态关联）管理，避免在店铺表中硬编码字段。创建店铺时自动查重（`name` 唯一约束），创建即上线无需审核。图片通过多态 `images` 表关联（`entity_type='shop'`），菜单以 `menu_items` 表独立存储。勘误和重复反馈统一写入 `feedbacks` 表，进入管理员审批流程。

### FD02 — 点评与问答互动模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD02-01 | 浏览点评与问答 | `ShopDetailPage.tsx` | `GET /interaction/comments/`, `/interaction/questions/` |
| FD02-02 | 店铺评分 | `ShopDetailPage.tsx` | `POST /ratings/`（合并入 shops 路由） |
| FD02-03 | 发表图文评论 | `ShopDetailPage.tsx` | `POST /interaction/comments/` |
| FD02-04 | 发布问答 | `ShopDetailPage.tsx` | `POST /interaction/questions/` |
| FD02-05 | 回复问答 | `ShopDetailPage.tsx` | `POST /interaction/answers/` |
| FD02-06 | 评论点赞 | `ShopDetailPage.tsx` | `POST /interaction/likes/` |

**设计实现思路**：  
评论区与问答区拆分为四张表（`shop_comments` / `comment_replies` / `shop_questions` / `question_answers`），不再用 `type` 字段混用。二级回复采用扁平设计：全部通过 `comment_id` / `question_id` 外键关联到一级内容，`reply_to_user` 仅记录被回复人用于 `@username` 前缀，无 `parent_id` 自引用。点赞统一通过 `content_likes` 多态表管理，点赞/取消通过 `is_active` 软删除实现 toggle。各内容的 `like_count` / `reply_count` 为冗余计数，在 DAO 层使用 `F()` 表达式原子更新。

### FD03 — 用户账户与收藏管理模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD03-01 | 用户注册与登录 | `LoginPage.tsx`, `RegisterPage.tsx` | `POST /auth/register`, `/auth/login` |
| FD03-02 | 查看个人资料 | `ProfilePage.tsx`, `UserProfilePage.tsx` | `GET /users/{id}` |
| FD03-03 | 修改个人信息 | `ProfilePage.tsx`（编辑模态框） | `PUT /users/{id}` |
| FD03-04 | 用户动态聚合展示 | `UserProfilePage.tsx` | `GET /activities/` |
| FD03-05 | 收藏/取消收藏店铺 | 店铺列表页/详情页 | `POST /favorites/toggle` |
| FD03-06 | 查看收藏夹 | `FavoritesPage.tsx` | `GET /favorites/` |
| FD03-07 | 查看消息通知 | `NotificationsPage.tsx` | `GET /messages/` |
| FD03-08 | 查看浏览历史记录 | `HistoryPage.tsx` | `GET /history/` |

**设计实现思路**：  
认证使用 JWT（`python-jose` 签发，`HS256` 算法），密码经 `bcrypt` 加密存储。收藏切换（toggle）通过 `is_active` 软删除实现——首次收藏 INSERT，取消设为 `is_active=False`，再次收藏复用记录，保留完整操作历史。动态由各 Service 在业务操作后手动写入 `activities` 表，采用 `user_id + created_at` 复合索引支持按时间倒序分页。浏览历史每用户-店铺仅保留一条记录（`unique_together` 约束），重复浏览自动更新 `viewed_at`。消息通知支持系统公告（`announcement`）和互动通知（`reply_comment`、`reply_answer` 等）。

### FD04 — 店铺发现与检索模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD04-01 | 浏览店铺列表 | `HomePage.tsx` | `GET /shops/?sort=favorite_count` |
| FD04-02 | 关键词搜索店铺 | `HomePage.tsx`（搜索框） | `GET /shops/?q=keyword` |
| FD04-03 | 分类与区域筛选 | `HomePage.tsx`（筛选栏） | `GET /shops/?category_id=&area_id=` |
| FD04-04 | 查看店铺详情 | `ShopDetailPage.tsx` | `GET /shops/{id}` |

**设计实现思路**：  
列表浏览默认按 `favorite_count` 降序排列，可选 `view_count` 或 `created_at` 排序，均直接利用 `shops` 表的冗余字段实现，无需聚合计算。关键词搜索使用 `WHERE name LIKE '%keyword%'` 结合 `aliases` JSON 列的模糊匹配。分类与区域筛选通过 `DictRel` 多态关联表查询：`WHERE entity_type='shop' AND dict_data_id IN (selected_ids)`。店铺详情页聚合查询 6 张关联表（`shops`、`menu_items`、`images`、`ratings`、`shop_comments`、`shop_questions`），使用复合索引 `(shop_id, created_at)` 高效加载评论和问题时间线。*补充说明：未来可引入全文索引优化搜索性能。*

### FD05 — 社区反馈与举报模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD05-01 | 举报不当内容 | 店铺详情页/评论区域 | `POST /feedbacks/`（type=complaint） |

**设计实现思路**：  
统一 `feedbacks` 表替代了需求文档中原生的 `complaints` 表，通过 `type` 字段区分举报（complaint）与勘误（edit_request）。举报对象采用多态关联（`target_type` + `target_id`），支持对 shop / comment / image 三种实体发起举报。原因通过 FK 引用 `dict_data` 表的值，前端通过 `/dict/data?type_name=反馈原因` 接口获取预设选项。防重复举报通过 `(user_id, target_type, target_id, type, status)` 组合逻辑在 DAO 层实现——同一用户对同一实体仅允许一条 pending 状态的未处理记录。

### FD06 — 管理员后台治理模块

| 子功能编号 | 子功能名称 | 前端页面/组件 | 后端接口 |
|:---|:---|:---|:---|
| FD06-01 | 处理举报反馈 | `admin/complaints/ComplaintPage.tsx` | `PUT /feedbacks/{id}/handle` |
| FD06-02 | 处理勘误反馈 | `admin/editRequests/EditRequestPage.tsx` | `PUT /feedbacks/{id}/approve` / `/reject` |
| FD06-03 | 合并重复店铺 | `admin/shops/ShopEdit.tsx` | `PUT /shops/{id}/merge` |
| FD06-04 | 封禁/解封店铺 | `admin/shops/ShopList.tsx` | `PUT /shops/{id}/ban` / `/unban` |
| FD06-05 | 封禁/解封用户 | `admin/users/UserList.tsx` | `PUT /users/{id}/ban` / `/unban` |
| FD06-06 | 发布系统公告 | `admin/announcements/AnnouncementCreate.tsx` | `POST /messages/announcement` |
| FD06-07 | 查看平台数据概览 | `admin/dashboard/Dashboard.tsx` | `GET /admin/dashboard/stats` |

**设计实现思路**：  
管理后台基于 `react-admin` 框架构建，前后端分离。管理员操作均记录 `operation_logs` 日志。封禁通过独立 `is_banned` 字段实现（与软删除 `is_active` 语义分离），封禁店铺/用户后全局过滤（所有查询自动加 `WHERE is_banned=FALSE`）。店铺合并需迁移从属店铺的全部关联数据（评论、收藏、问答、图片）至主店铺，通过 `merged_into_id` 自引用建立重定向；从属店铺 `is_active=False`，原名称存入主店铺的 `aliases` JSON 字段。平台仪表盘通过 `COUNT(*)` 聚合查询展示核心指标，近 7 日趋势按 `created_at` 分组统计。

## 模块间调用关系

```
用户登录 ──→ FD03（JWT 签发）
               │
               ├──→ FD04（店铺发现与检索）──→ FD01（查看店铺详情）
               │                                    │
               │                                    ├──→ FD02（发表评论/问答/点赞）
               │                                    │       │
               │                                    │       └──→ FD03（生成动态 + 消息通知）
               │                                    │
               │                                    ├──→ FD05（举报不当内容）
               │                                    │
               │                                    └──→ FD03-05（收藏/取消收藏）
               │
               └──→ FD06（管理员后台）
                        │
                        ├──→ FD05（处理举报/勘误工单）
                        ├──→ FD01（封禁店铺 / 合并店铺）
                        └──→ FD03（封禁用户 / 发布公告 / 发送消息）
```

**文字说明**：  
- **用户侧**：所有用户操作（浏览、评论、点赞、收藏、举报）均需先通过 FD03 的 JWT 认证。FD04 作为前端首页入口，引导用户进入 FD01（店铺详情）。FD01 详情页聚合 FD02（互动）和 FD05（举报）的操作入口。FD02 的互动操作（评论、点赞）会触发 FD03 的动态生成和消息推送。
- **管理侧**：FD06 管理员后台接收 FD05 产生的工单（举报/勘误），审批后执行对应的治理操作（FD01 封禁店铺/合并店铺、FD03 封禁用户/发送通知）。所有管理操作均写入 `operation_logs` 审计日志。
