# 前端适配新接口调整方案

> **版本**：基于后端全新 API 规范（`前端接口文档.md` + `openapi.json`）  
> **目标**：修复白屏，前端所有页面改用真实后端接口  
> **原则**：直接对齐后端字段名，不在 API 层做额外映射

---

## 一、核心数据结构调整

### 1.1 类型定义 — `types/shop.ts`

**现状**：camelCase 字段，独立 `category`/`area` 字符串
**目标**：直接使用后端 `ShopResponse` 字段

```typescript
// 新 — 直接对齐后端
export interface ShopCardData {
  id: number;
  name: string;
  average_rating: number;
  view_count: number;
  favorite_count: number;
  comment_count: number;
  cover_image: string | null;
  dict_data: DictDataItem[];
  is_favorited: boolean;
  created_at: string;
}

export interface DictDataItem {
  id: number;
  name: string;
  // extra?: any; // 按需
}

export interface ShopDetail extends ShopCardData {
  rating_distribution: RatingDistribution;
  menu_items: MenuItem[];
  images: ImageItem[];
  is_banned: boolean;
  user_rating: { score: number } | null;
  updated_at: string;
}

export interface RatingDistribution {
  star_1: number;
  star_2: number;
  star_3: number;
  star_4: number;
  star_5: number;
  total: number;
}
```

## 四、关键注意事项

### 4.1 dict_data 的 category/area 提取

店铺响应中品类、区域等信息都在 `dict_data[]` 数组里。前端需要一个**轻量字典 Caching 层**：

```typescript
// 页面初始化时（或懒加载）
const dictTypes = await fetchDictTypes(); // GET /dict/types
// 返回 [{id:1, name:"品类"}, {id:2, name:"区域"}, {id:3, name:"就餐方式"}]

// 在 ShopCard / ShopInfoSection 中提取显示名
const categoryNames = shop.dict_data
  .filter(d => isCategory(d.id, dictTypes))
  .map(d => d.name);
```

建议将 `getDictName(id, dictTypes)` 封装到 `src/config/dict.ts` 工具函数中。

### 4.2 浏览历史独立列表接口

`GET /users/me/history` 返回的列表项需要携带店铺基本信息（至少 `shop_id` + `shop_name`），否则前端无法展示历史卡片。若后端未包含，建议补充。

### 4.3 评分分布字段名

前端 `RatingSection.tsx` 中 `ratingDistribution[1]` ~ `ratingDistribution[5]` 需改为 `rating_distribution.star_1` ~ `star_5`。

### 4.4 收藏切换返回值

`POST /favorites/toggle?shop_id=X` 返回 `{is_favorited, favorite_count}`，前端乐观更新依赖此返回值。
